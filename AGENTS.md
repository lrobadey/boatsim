# Repository guidance

Use systems thinking and first-principles reasoning to solve issues. Collaborate with the user,
resolving ambiguities with requests, plans, or ideas. Only do browser tests if the user explicitly
tells you to. Update relevant skills as you work when new information, context, or knowledge would
help future agents work more efficiently and effectively.

## Project context

Before architectural or gameplay planning, read [docs/vision.md](docs/vision.md), the project's
long-term vision and design philosophy. Prioritize composable capabilities and constraints,
shared authoritative simulation state, and meaningful, legible consequences while preserving
first-person physical presence.

The vision informs decisions; it does not authorize implementation. Its aspirations and suggested
autonomous-captain experiment are not an approved roadmap or committed next priority. Section 15
is a dated historical snapshot, not a current implementation or validation report.

[PLAN.md](PLAN.md) records the original vertical-slice plan. [handoff.md](handoff.md) contains
development handoffs; check entry dates and verify current repository state before relying on them.
